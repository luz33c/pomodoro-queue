桌面端：共享包 + Electrobun 本地包

新增 packages/app 放 web 与桌面共用的 /app 界面和查询；新增 apps/desktop：Electrobun 主进程开窗口，加载 views://mainview，界面是 Vite 构建的 React SPA，复用共享包的页面。 web 只把 dashboard 的实现搬进共享包，自己留一层薄包装。登录不在本计划内。

窗口 加载本地包 views:// 复用 共享包，不让 web 出桌面构建 主进程 bun（2.x 默认） 路由 hash history · 代码式 登录 先占位

开发与打包流程

pnpm run dev:desktop

  1. predev：构建 @tsu-stack/i18n
  2. dev:view：Vite 在 :5180 起 view，带 HMR
  3. dev:shell：electrobun dev --watch 启动主进程（dev 渠道）
  4. 主进程探测到 dev server → 窗口打开 http://localhost:5180
  5. 改共享包或 view 的代码 → 热更新；改主进程 → 自动重启

pnpm run build:desktop

  1. build:view：vite build → apps/desktop/dist/view
  2. electrobun build --env=stable：打包 bun 主进程
  3. copy：dist/view → Resources/app/views/mainview
  4. 输出 build/ 与 artifacts/（只构建当前平台）
  5. 运行时：窗口加载 views://mainview/index.html#/

风险与待验证

Electrobun 2.x 很新

2.0.4，文档有前后不一致（如 mainProcess 默认值），API 名称以 spike 实测为准。

Hutch 工具链

首次运行要联网下载；CI 需要 macOS、Windows、Linux 各自的原生 runner。

TypeScript 7

devkit 的 tsconfig 可能不兼容；不兼容就像 apps/native 一样钉 TS 6。

views:// 的 Origin

决定 API 是直连还是主进程代发（决策 4）。

注入顺序

漏调 configureAppApi 时渲染会抛出明确错误，不会悄悄失败。

以后接登录

推荐系统浏览器走 web 登录 + Clerk OAuth PKCE，token 留在主进程；服务端加 acceptsToken（3.20.1 已支持）。
