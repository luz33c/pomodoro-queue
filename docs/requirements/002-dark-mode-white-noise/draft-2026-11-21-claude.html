02五套声音方案一览

点任意一张卡片，下面的屏幕就切到那套声音方案。五套用的都是方案 1 的界面，换的只是声音这一块。为了不和原文档的「方案 1–5」混淆，声音方案用字母 A–E。

五套共用的规则
  • 声音只在「专注进行中」自动播放，1 秒淡入。暂停时 0.4 秒淡出，继续时接上。
  • 休息默认安静。哪套方案在休息时出声，会在它的说明里写明。
  • 还剩 1 分钟的提醒和 island 的气泡照旧，声音不为它们压低，也不抢它们。
  • 选了哪种声音跟账号走，换设备也在；音量和静音记在这台设备上。
  • 没有队列时在面板里点一种声音，试听 3 秒就停。
  • 收起主窗口后声音继续，island 展开后能调音量和静音。
  • 声音是循环的环境音，不带旋律，不带人声。

04声音素材：演示放了 8 种，都是合成的占位

点「试听」听 3 秒。这里的声音是浏览器现场合成的，只为了让演示能响、让你分得清哪种是哪种。正式版换成录制或采购的无缝循环素材，位置和时机不变。

要准备的素材要求原因
每种声音一段循环60 秒以上，首尾无缝太短会听出重复；有接缝会每分钟「咔」一下
响度所有素材统一到同一响度，具体数值待音频同学定切换声音或混音时音量不跳
格式和大小AAC 或 Opus，96 kbps 上下60 秒约 0.72 MB，8 种不到 6 MB，可以随安装包带上
提示音（只有方案 B 要）两段，各 0.5 秒：专注→休息、休息→专注不看屏幕也知道换阶段了
场景插画（只有方案 C 要）每个场景一张首页背景、一张休息页背景，深浅两套场景把画面和声音绑在一起

06暗色模式：只给主窗口补一套深色取值

这一节的规则和取值已经进了 001，这里保留原样，方便和声音一起看。下面两块用的是演示里同一套组件，左边浅色、右边深色。表格里的色值是从这两块上实时读出来的，改了样式表这里会跟着变。

规则
  • 外观三选一：跟随系统（默认）、浅色、深色。入口在窗口右上角「外观」。

  • 切换立即生效。专注进行中切换，倒计时和声音不受影响。

export const AMBIENT_SOUND_IDS = ["rain", "wave", "fire", "stream", "wind", "white", "pink", "brown"] as const;
export type AmbientSoundId = (typeof AMBIENT_SOUND_IDS)[number];

export type SoundLayer = { gain: number; id: AmbientSoundId };
export type SoundPrefs = { duringBreak: boolean; sound: AmbientSoundId | "off" };

/** Returns the layers that should be audible right now; an empty list means silence. */
export function decideSound(phase: IslandSnapshot["phase"], prefs: SoundPrefs): SoundLayer[] {
  if (prefs.sound === "off") return [];
  if (phase === "focus") return [{ gain: 1, id: prefs.sound }];
  if (phase === "short_break" || phase === "long_break") return prefs.duringBreak ? [{ gain: 1, id: prefs.sound }] : [];
  return []; // "paused" and "waiting" stay silent
}

10我的建议、要你定的事、实现前要验证的事

建议：先做 A「声音胶囊」，暗色和 island 上的音量、静音一起带上。 A 的设置里存「一组层」而不是「一个 id」，之后往 B 和 D 走不用迁移数据。B 的「休息时换一种声音」可以作为 A 的一个开关并进来。C 要等画师的场景插画。E 依赖 AI 估算先上线。D 等有人提出来再做。这只是我的判断，听完演示后以你的感受为准。

要你定的事

选哪套声音方案，或者怎么混搭

五套可以叠加：例如 A 的胶囊加 B 的休息声音。

默认：按上面的建议，先做 A。

首发几种声音

演示放了 8 种。每多一种要多一段素材，安装包大约多 0.7 MB。

默认：首发 6 种：雨声、海浪、篝火、溪流、白噪音、棕噪音。

休息时默认有没有声音

安静更像「歇一下」；有声音更连贯。

默认：没有，做成可以打开的开关。

App 的默认外观要不要改成跟随系统

现在 __root.tsx 里默认是深色，改了会影响整个 App。

默认：改成跟随系统。

哪些跟账号、哪些跟设备

两台设备的喇叭和环境不一样。

默认：选了哪种声音跟账号；音量和静音跟设备。

两台设备同时开着，要不要都响

都响最简单；只让一台响要额外判断哪台在用。

默认：都响，各自能静音。

长休息的动效

原文档写「长休息拉伸」，方案 1 实际还是走去喝咖啡。

默认：保持方案 1 现状，等动效素材时一起定。

浅色主题要不要顺手修对比度

橙底白字 2.77:1，次要文字 3.56:1。修了会和原稿略有出入。

默认：先不动，和设计一起定。

实现前要验证的事

隐藏的窗口还能不能出声

风险：桌面壳的窗口隐藏后，音频可能被系统挂起。

怎么验证：在桌面壳里放一段循环声音，隐藏窗口 30 分钟，看有没有中断。

没有用户操作时能不能自动出声

风险：App 重启后恢复专注中的队列，这时没有点击。

怎么验证：桌面壳冷启动后直接播放，分别在桌面壳和浏览器里试。

循环有没有接缝

风险：压缩格式解码后首尾可能多出几毫秒静音。

怎么验证：用 AudioBufferSourceNode 循环，每种素材听 10 分钟。

内存

风险：60 秒立体声解码后约 21 MB；方案 D 三层同放就是 63 MB。

怎么验证：三层同放时看内存；太高就改单声道或缩短素材。

深色取值没有经过设计确认

风险：本页的深色是我按第 06 节的规则配的，对比度够，但观感要设计来判断。

怎么验证：设计过一遍 token 表和演示。

方案 E 依赖的 AI 字段

风险：估算接口的名字和返回结构在规划文档里没有找到。

怎么验证：和做估算的人确认能不能多返回一个声音字段。
