为什么要分这么多盒子？

🧬

少复制

API 类型、健康检查规则、环境变量、日志规则可以共同使用。

🔐

少漏门锁

界面守卫负责引导登录，受保护的 API 仍会独立校验身份；不能只靠页面拦住访问。

🧭

少迷路

路由、页面、功能、通用组件各归各位；lint 会阻止不该有的跨层引用。

它现在长到哪一步了？

已经有的地基

多端骨架是通的

  • 网站支持 SSR 与 SEO，产品 App 是独立 SPA；两者共用 UI 与国际化资源
  • 产品 App 同时构建浏览器版和桌面版，桌面壳已接入，登录仍为占位
  • 手机和扩展会调用同一套 oRPC API
  • Docker 中 API 等迁移完成，网站等 API 健康；产品 App 静态服务独立启动
  • 日志、健康检查、环境变量都有独立积木
还没有大量业务

这更像高级模板

  • 当前共享 API 只有健康检查和受保护的示例数据
  • 当前 schema 已移除旧认证表，尚未添加业务表
  • core 目前主要放健康检查和资源工具
  • 真正的业务领域模块还等着加入

一句话结论

这是一个网站、产品 App、手机与扩展共用后端的 TypeScript 单仓库。产品 App 的同一套界面可在浏览器或桌面壳中运行，桌面登录尚未接入。添加业务时，沿着“数据库 → 共同规则 → API → 页面”分工实现。
