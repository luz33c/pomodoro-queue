# Database Package

`@tsu-stack/db` owns the PostgreSQL schema, relations, migrations, and table-level query functions. It uses Drizzle ORM v1 with relational queries v2 on the `postgres-js` driver and runs on the server only.

## Layout

```text
packages/db/
  drizzle.config.ts   drizzle-kit config; reads src/schema/index.ts
  migrations/         generated by drizzle-kit; never edit by hand
  src/
    index.ts          package entry; re-exports only
    client.ts         db instance, DbExecutor type, checkIsDbReady
    migrate.ts        migrateDatabase, run at production server startup
    schema/
      index.ts        re-exports every table file
      relations.ts    defineRelations over the whole schema
      todo.ts         one file per table
    queries/
      index.ts        re-exports every query file
      todo.ts         query functions for the todo table
```

`todo` is the reference table. Copy its schema and query files when adding a table.

## Entry Points

| Import                  | Exports                                                                                      |
| ----------------------- | -------------------------------------------------------------------------------------------- |
| `@tsu-stack/db`         | `db`, `DbExecutor`, `checkIsDbReady`, `migrateDatabase`, and the `drizzle-orm/sql` operators |
| `@tsu-stack/db/schema`  | tables and row types, for example `todo`, `Todo`, `NewTodo`                                  |
| `@tsu-stack/db/queries` | table-level query functions, for example `listTodos`, `getTodo`                              |

`client.ts` imports `@tanstack/react-start/server-only`, so `@tsu-stack/db` and `@tsu-stack/db/queries` must stay out of client bundles.

Inside the package, import through `#/` subpaths such as `#/client` and `#/schema/todo`, per [TypeScript conventions](../../.agents/typescript.md#module-resolution).

## Naming

- The directory names the role, so file names carry no role suffix: `schema/todo.ts` and `queries/todo.ts`, never `todo.schema.ts` or `todo.queries.ts`.
- Name both files after the table in kebab-case. A `media_asset` table lives in `schema/media-asset.ts` and `queries/media-asset.ts`.
- Name the table export in camelCase (`todo`, `mediaAsset`) and its row types `Todo` and `NewTodo`.

## Schema

- Define tables with `snakeCase.table` from `drizzle-orm/pg-core`. Properties stay camelCase and columns become snake_case, so omit column names: `ownerId: text()`, not `text("owner_id")`.
- Start from the `todo` columns: a `uuid` primary key with `defaultRandom()`, and `createdAt` and `updatedAt` as `timestamp({ withTimezone: true })`.
- Export the row types next to the table: `typeof table.$inferSelect` and `typeof table.$inferInsert`.
- Re-export each new table file from `schema/index.ts`. Both `relations.ts` and `drizzle.config.ts` read the schema from there, and that is what makes `db.query.<table>` available.
- Declare relations in `relations.ts` by passing a callback to `defineRelations`; see the [Drizzle relations v2 docs](https://orm.drizzle.team/docs/relations-v2).
- Store a Clerk user ID in a `text` column such as `ownerId`, without a foreign key. There is no local user table; see [Auth patterns](../../.agents/auth.md#database-boundary).
- Every schema change needs a generated migration. Follow [Workflow](../../.agents/workflow.md#database-schema-changes).

## Queries

`queries/<table>.ts` holds the reusable reads and writes for one table.

- Name functions `list<Table>s`, `get<Table>`, `create<Table>`, `update<Table>`, and `delete<Table>`. Add a qualifier only when it carries meaning, for example `getTodoBySlug`.
- Take the identifying fields as one object argument, and `executor: DbExecutor = db` as the last argument so callers can pass a transaction.
- Read with relational queries, `executor.query.<table>.findMany()` and `findFirst()`. Their `where` and `orderBy` take objects: `{ where: { id, ownerId }, orderBy: { createdAt: "desc" } }`. The callback form `where: (table, { eq }) => ...` belongs to the old relational API and does not apply here.
- Scope every read, update, and delete of user-owned rows by `ownerId`.
- Never run `update` or `delete` without a `where`.
- Destructure the columns a function may write or filter on instead of passing caller objects straight to `values()`, `set()`, or `where`, so extra fields are never written or matched.
- Return the written row with `.returning()` instead of reading it back.
- Return `null` when no row matches, and let the oRPC handler turn that into a typed error such as `errors.TODO_NOT_FOUND()`.
- Return rows as Drizzle produces them. The router converts them to transport shapes, such as `Date` to an ISO string; see [oRPC patterns](../../.agents/orpc.md).
- Do not log or throw oRPC errors here. Handlers own request-scoped logging; see [Logging](../../.agents/logging.md).
- Zod contracts shared by the API and the web app belong in `packages/core`, not here; see [Core package patterns](../../.agents/core.md).

## Package Queries Or Router Queries

- Put a function in `packages/db/src/queries/` when it reads or writes one table and more than one caller can use it, for example several routers, a webhook, or a script.
- Keep it in the router's own `queries.ts` when it serves one procedure, such as a cross-table aggregation for one screen; see [oRPC patterns](../../.agents/orpc.md#router-folder-shape).

## Transactions

Pass `tx` as the executor to run several query functions atomically:

```ts
await db.transaction(async (tx) => {
  const created = await createTodo({ ownerId, title }, tx);
  await updateTodo({ id: created.id, ownerId }, { completed: true }, tx);
});
```
